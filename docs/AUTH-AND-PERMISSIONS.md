# KubePilot — auth and permissions

This is the authorization spec. If the UI and this file disagree, this file wins until we change it on purpose.

## Login

- Identifier: `username` (case-insensitive, stored lowercase) + password.
- No self-signup. No magic links. No in-app SSO (Cloudflare Access may still SSO at the edge).
- Password hashing: Argon2id.
- Session: HttpOnly, Secure, SameSite=Lax cookie named `kubepilot_session`, signed with `SESSION_SECRET`. Session row in MongoDB.
- Idle timeout: **8 hours** (`lastSeenAt` refresh on requests). Absolute lifetime: **24 hours**. Either expiry logs the user out.
- Concurrent sessions: allowed. Disable user or logout-all (owner action on a member) deletes that user’s sessions.
- Failed login: generic error to the client; audit `login_failed` with username attempted and IP.
- Disabled user: login rejected; audit `login_failed` with reason `disabled`.

### First login (members)

`mustChangePassword=true` on create and on owner reset. After login, only `GET /api/auth/me`, `POST /api/auth/password`, and `POST /api/auth/logout` are allowed until the password is changed. Then the flag is cleared.

Owner **cannot** use `POST /api/auth/password`. Owner password is only set from `OWNER_PASSWORD` at process start.

## Owner

- Role `owner`. Exactly one user with this role.
- On **every** process start: if no owner exists, create from `OWNER_USERNAME` (default `owner`) + `OWNER_PASSWORD`. If an owner exists, keep that username and **set the password hash from `OWNER_PASSWORD`**.
- `OWNER_PASSWORD` is required. If missing or empty, the process is not ready.
- If the boot password differs from the stored hash, update the hash and delete all owner sessions so the new password is required immediately.
- Owner cannot change password in the UI. To rotate: change the Secret, restart pods.
- Full cluster access in the UI. Skips permission-set checks.
- Exclusive modules: members, permission sets, audit, app settings.
- Exclusive namespace: the **install namespace** (`POD_NAMESPACE`).
- Cannot be deleted or disabled through the UI.
- Cannot be assigned a permission set (meaningless).

## Members

Created only by the owner.

| Field | Rules |
| --- | --- |
| username | Unique, `[a-z0-9][a-z0-9._-]{1,31}`, lowercase |
| displayName | Required, 1–80 chars |
| password | Generated by the server (24+ chars, mixed). Shown **once** in the create/reset response. Never stored plaintext. Never shown again. |
| permissionSetId | Required. Must reference an existing set. |
| enabled | Default true |

### Invite

1. Owner fills username, display name, and permission set.
2. API creates the user with a generated password and `mustChangePassword=true`.
3. UI shows username + password with copy buttons and a warning that this is the only time the password is visible.
4. Owner shares those credentials out of band.

There is no email, invite token, or expiry on the password other than “they must log in and change it”. If they lose it before first login, owner uses Reset.

### Reset password

Owner clicks Reset. Server generates a new password, sets `mustChangePassword=true`, deletes existing sessions for that user, returns the new password once. Audited as `member_password_reset`.

Members cannot self-reset.

### Disable

`enabled=false`. Existing sessions deleted. Login fails. Audit history remains. Owner can re-enable.

### Delete member

Deletes the `users` document and sessions. **Audit logs are kept.** Each audit row stores `username` and `userId` snapshots so history still reads after delete.

### Namespace grant

Namespace access lives on the **permission set**, not the member. Everyone assigned to a set gets the same namespaces.

- `namespaceScope: "all"`: all current and future namespaces **except the install namespace**.
- `namespaceScope: "selected"`: union of `namespaces` (exact names) and `namespaceRegex` (Go RE2, full-name match with implicit `\A(?:pattern)\z`). At least one name or pattern is required.
- Exact `*` is rejected; use `all` instead.
- Namespace names that do not exist yet may still be listed; list/get will just be empty/404 until they exist. Regex matches future names automatically.
- Invalid regex is rejected on save.
- Cluster-scoped modules (Nodes, PVs, CRDs, …) **ignore** the namespace grant. They require the module grant itself.

Existing members are migrated once at process start: if several people shared a set but had different namespace lists, that set is cloned per distinct list and members are reassigned. Unused sets default to `all`. Member `namespaces` fields are then cleared.

### Install namespace (owner only)

The namespace the dashboard pod runs in (`POD_NAMESPACE` from the Downward API). Detected at runtime — not hardcoded as `kubepilot`.

- Owner: can see and operate on it like any other namespace (the app itself, its Secret, etc.).
- Members: **never**. Not in the switcher, search, lists, Helm, events, or YAML apply. API returns 403 (audited).
- `["*"]` / `all` does not include it.
- Owner cannot add it to a permission set’s exact-name list (save rejected). A regex that would match it still does not grant it.
- Members cannot delete or rename this namespace even if they have `namespaces.delete`.

This stops members from editing the dashboard Deployment, reading `OWNER_PASSWORD` / `MONGODB_URI` from its Secret, or otherwise taking over the console.

## Permission sets

A named bundle of grants. Assigned to one or more members. Changing a set takes effect on the next API call (permissions loaded per request, not baked into the session).

### Grant shape

```json
{
  "name": "Pod Operator",
  "description": "Restart and logs in granted namespaces",
  "namespaceScope": "selected",
  "namespaces": ["prod"],
  "namespaceRegex": ["team-.*"],
  "grants": {
    "pods": ["view", "logs", "delete"],
    "deployments": ["view", "restart", "scale"],
    "events": ["view"],
    "metrics": ["view"]
  }
}
```

- If a module key is missing, the module is **off**: hidden in the sidebar, all APIs 403.
- If a module is present, only listed actions are allowed. `view` is required for any other action on that module; the API treats “scale without view” as invalid and owner UI should not allow saving it.
- Unknown module ids or actions are rejected on save.
- Templates and new sets default to `namespaceScope: "all"`.

### Built-in templates

Owner can clone these. Clones are normal sets (`builtinTemplate` null). Editing the clone does not change the template definition in code.

**Viewer**

- All catalog modules: `view` only (including `events`, `metrics`).
- Secrets: `view` but **not** `reveal`.
- No `yaml_edit`, `logs`, `exec`, mutations, Helm writes.
- Nodes: `view` only (no cordon/drain).

**Operator**

- Viewer plus: `logs`, `restart`, `scale`, `trigger` (CronJobs), Pod `delete` (not workload delete), no `exec`, no `yaml_edit`, no `reveal`, no Helm writes, no Access Control writes, no CRD definition writes.

**Admin** (cluster ops, not KubePilot owner)

- All module actions except owner-only settings.
- Includes `exec`, `yaml_edit`, `reveal`, Helm install/upgrade/rollback/uninstall, node cordon/drain, Access Control CRUD.

Templates do not include `settings.*` modules. Those are owner-only in code, not grantable.

## Enforcement rules

1. Owner: allow (except nothing can delete the owner; owner cannot change password via API).
2. Member disabled: login `401`; existing cookie `403` and session deleted.
3. Module missing from set: 403.
4. Action missing: 403.
5. Namespaced resource: namespace must be allowed by the permission set (`all`, exact name, or full-name regex), **and must not be the install namespace**.
6. Cluster-scoped resource: namespace grant is ignored; module grant is enough.
7. YAML apply is `yaml_edit` on **that** module, not a global YAML superpower.
8. Helm: release namespace must be allowed by the set and must not be the install namespace; cluster-wide listing is filtered.
9. Search and overview only query allowed modules + namespaces (install namespace omitted for members).

Denials are audited ([AUDIT.md](AUDIT.md)).

## Module and action matrix

Legend:

- **Scope:** `ns` = namespaced (filtered by the permission set’s namespace grant). `cluster` = cluster-scoped (namespace grant ignored). `app` = KubePilot, not Kubernetes.
- **Base actions:** `view`, `create`, `edit`, `delete`, `yaml_edit` unless a row says otherwise.
- Extra actions are listed explicitly.

### KubePilot (owner only)

| Module id | Scope | Actions | Notes |
| --- | --- | --- | --- |
| `settings.members` | app | view, create, edit, delete, reset_password | Owner only in code |
| `settings.permission_sets` | app | view, create, edit, delete | Owner only |
| `settings.audit` | app | view, delete | Owner only |
| `settings.app` | app | view, edit | Session timeouts, metrics source, Helm repos |

### Cluster

| Module id | Scope | Actions | Extra |
| --- | --- | --- | --- |
| `cluster.overview` | cluster | view | Aggregates only from modules the user can view |
| `namespaces` | cluster | view, create, edit, delete, yaml_edit | Listing namespaces for the switcher: owner sees all; member sees granted names only, even if this module is off (switcher is not a leak of ungranted namespaces). Install namespace is omitted for members. |

A member **without** `namespaces` module cannot create/edit/delete namespaces. They can still pick granted namespaces in the switcher.

A member **with** `namespaces.create` can create a namespace. It appears in their switcher only if the set is `all` or the new name matches an exact name or regex. They cannot create a namespace whose name equals `POD_NAMESPACE`.

### Nodes

| Module id | Scope | Actions | Extra |
| --- | --- | --- | --- |
| `nodes` | cluster | view, edit, delete, yaml_edit | `cordon`, `drain` (uncordon is `cordon`) |

`delete` on a node is allowed in the matrix (Lens-style) but the UI must confirm strongly. `edit` covers labels/taints.

| Module id | Scope | Actions | Extra |

Helm `view` is required for any Helm write action.

## Action catalog (canonical verbs)

Use these strings in `grants` and in audit `action` fields (audit may prefix, see [AUDIT.md](AUDIT.md)):

`view`, `create`, `edit`, `delete`, `yaml_edit`, `logs`, `exec`, `scale`, `restart`, `rollback`, `trigger`, `cordon`, `drain`, `reveal`, `install`, `upgrade`, `uninstall`, `reset_password`

Uncordon is stored as action `cordon` with detail `uncordon`. Helm rollback uses `rollback`.

## Sidebar mapping

The React sidebar shows a module only if the user is owner or the set contains that module with `view`. Grouping:

- Cluster: overview, nodes, namespaces, events
- Workloads: overview, pods, deployments, statefulsets, daemonsets, replicasets, jobs, cronjobs
- Config: configmaps, secrets, resourcequotas, limitranges, hpas, pdbs, priorityclasses, runtimeclasses, leases
- Network: services, endpoints, ingresses, ingressclasses, networkpolicies
- Storage: pvcs, pvs, storageclasses
- Access control: serviceaccounts, roles, rolebindings, clusterroles, clusterrolebindings
- Custom resources: crds, grouped CR instances
- Helm
- Settings (owner): members, permission sets, audit, app
